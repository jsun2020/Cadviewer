## 已知遗留（未做，且是有意为之）

| 项 | 影响 | 归属 |
| --- | --- | --- |
| SHX 笔画字体绘制的文字在 PDF 中不可检索 | TrueType 部分已内嵌子集、可选可搜；SHX 是笔画字库，没有可嵌入的字形轮廓字体，只能以线条绘制 | 设计如此，非缺陷 |
| 缺 `hztxt.shx` 等 7 款字库时以 `gbcbig.shx` 顶替 | 字形与参考件不同（笔画体 vs 宋体），位置与尺寸一致；已逐条告警并给出受影响实体数 | 需用户自行安装原字库 |
| 8 个样式压根没写字体名，中文靠兜底字库绘制 | 同上，已告警。样例中影响 144 个实体（含图名） | 图纸自身问题，非缺陷 |
| HATCH 填充未绘制 | 样例中 6796 处填充缺失 | Phase 5 |
| MLINE 未绘制 | 需要先解析 MLINESTYLE 表，否则画出的线 AutoCAD 根本不打印 | Phase 5 |
| **导出慢：26 页约 9 分半（目标 <15 秒）** | 块展开未按页做包围盒剔除，等于对整份文档做 26 次完整遍历 | Phase 6 |
| 视觉差分工具与 15%/6%/3% 门限 | 目前只有人工比对参考件 | Phase 5 |
| PDF 图层（OCG） | 参考件默认带此能力，也是极好的逐层调试手段 | Phase 5 |
| `BuildReport::skipped` 按全文档累计而非按页 | 每页显示相同的跳过计数，读起来有误导 | 任意阶段，成本很低 |
| GUI 从未真机验证 | 无显示自动化环境；仅验证了 release 构建与转换器 | 需人工验证 |

## 本次重建中发现、但属于**既有代码**的缺陷

`src/dxf.rs`（已删除的旧 SVG 渲染器）中的 `bulged_polyline` 存在符号错误，
会把所有 bulge 圆弧**沿弦镜像**。新实现已按 DXF 的 sagitta 定义重新推导并修正
（正 bulge 为逆时针）。如果历史构建的圆弧看起来"鼓错方向"，成因即此。
